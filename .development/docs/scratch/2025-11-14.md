**Mission:** Reliable and cheap agents that actually solve real-world tasks and learn on the job.

**Why is building Agents hard today?**
Current Agent development is split into 4 distinct places to optimize:

- **ReAct loop** – LLM calling tools in a loop. Powerful, but linear.
- **Context engineering** – hand-crafted prompt and context management to coax the right algorithmic behavior from the ReAct loop
- **Orchestration** \- Scripting ReAct calls and context to get the right overall program flow.
- **Foundational Model** \- training models with longer tasks and multi-step reasoning traces

Each of these live in a different world (pre/post-training, prompts, history compression, Python).
Optimization requires translating domain-specific intent between each of the four worlds to get the right behavior.

**Nemo Synapse proposes an alternative approach:**
Agents are objects (in the software sense), with methods and state programmed by developers and themselves.

- Developer writes methods (initially)
- Agent generates methods (during tasks)
- Agent Optimizer improves methods (during execution, based on past traces)

All on the same object, all in Python, all optimizable together

Then agents become:

- **~~ReAct loop~~** → Agent-generated python code
- **~~Context engineering~~** → Python calls to manage context
- **~~Orchestration~~** → Developer- or Agent-generated Python code
- **~~Foundational Model~~** → Models are trained on more code than ReAct traces

No more translation. No more boundaries. Just methods that get better over time.

We call these “Procedurally Generated Agents” (ProGen Agents or “Vibe Agents”).
