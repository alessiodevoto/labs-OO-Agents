**Mission:** Reliable and cheap agents that actually solve real-world tasks and learn on the job.
**Approach**: Building Vibe Agents (or Object Oriented Agents) – Agents that are objects within a Python runtime with minimal APIs for orchestration, memory, and task management.

**Summary**

- **Runtime almost stable**: [Agent-as-Python-object runtime](https://gitlab-master.nvidia.com/interactive-agents/nemo_oo_agents) with APIs for context, history, tools, and tracing.
- **Capability tests passing**: Models mostly understand how to operate inside 006 agents across a wide set of interface tasks.
- **Agentic optimization**: Building trace analysis, mechanical checks, and a custom trace viewer to improve agents from eval data.
- **Next: benchmarks**: DABStep (w/ KGMON), SWEBench, Tau-Bench, LoCoMo, LongMemEval.

**Latest Results:**

- **Runtime Converging**: The agent-as-object runtime is stabilizing with clean APIs. We now have a suite of capability tests that verify models understand how to operate inside a 006 agent – testing a wide set of models across a wide set of interface tasks. With this foundation, we can now build towards benchmarks. Key features:
  - **Agent = Python object**: Methods become capabilities, state persists across calls
  - **Full OTel tracing**: One-liner `enable_tracing()` with JSONL export and Langfuse support
  - **Context API**: `self.context.set/get/remove()` for dynamic context management
  - **Event history**: `self.history` with search, and IPython-style `Out[n]` execution outputs
  - **Tools & subagents**: Methods are tools; agents can spawn subagents by creating an instance and calling it's methods.

  ```python
  class MyAgent(Agent, llm=my_llm):
    def __init__(self):
        super().__init__()
        self.memory = []       # Agent state - just Python
        self.knowledge = {}    # You control the data structures

    async def remember(self, fact: str):
        """Store a fact for later retrieval."""
        self.memory.append(fact)  # Normal Python code

    # LLM calls use strongly-typed interfaces (similar to DSPy)
  ```

- **Towards Agentic Optimization**: We're building towards a system that can improve agents from eval data. Although it's early, we're working on the following:
  - **Trace Analyzer Agent**: An agent that can navigate execution traces and perform root cause analysis on failures
  - **TraceExplorer**: A programmatic API for agents to explore traces (find messages, tool calls, errors)
  - **Mechanical Checks**: Automated detectors for common failure patterns (e.g., excessive agent recursion, execution errors)
  - **Custom Trace Viewer**: We opted to build a custom trace viewer after finding that off-the-shelf solutions (Phoenix, Langfuse, W&B) slowed debugging velocity with excessive click-depth and unreadable "raw JSON" displays. The trace viewer now supports also annotation to build eval sets for the trace analyzer.

Any tooling we've built is to unblock applied research or experiment with the developer journey from single engineer to production. We would rather build on NVIDIA software and infra, but for our use case (start of the user journey, small team of engineers running things locally and ad-hoc), we haven't found the tools that work. However, we strongly believe that NVIDIA should support this developer journey from single dev running local, to small team, to limited rollout, to full production. Please reach out if you would like to collaborate on the agent developer tools or developer journey.

- **Building Towards Benchmarks**: We've selected benchmarks to stress-test agent-as-object across different capability dimensions:

  | Domain | Benchmark | Why |
  |--------|-----------|-----|
  | Software Engineering | SWEBench | The team uses coding agents daily. We want to test how memory, orchestration, and context management improve coding—and build SWE agents to accelerate development (e.g., GitLab issue → MR). |
