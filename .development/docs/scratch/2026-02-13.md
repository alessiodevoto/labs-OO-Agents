**Mission:** Reliable and cheap agents that actually solve real-world tasks and learn on the job.

**Approach**: Building "Vibe Agents" (or Object Oriented Agents) – Agents that are objects within a Python runtime with minimal APIs for orchestration, memory, and task management: see [our code repo](https://gitlab-master.nvidia.com/interactive-agents/agent006).

**Summary**

- **Agents: Where the Puck is Going** – We articulated our [vision of agents as software](https://docs.google.com/document/d/1hkjlzjzxVca6vszq01p07l6xRd96iOHnaZiSDORQvv8/edit), explained it in the context of recent advances across the industry, and outlined the big open problems for Agents
- **Agent006 x SWE Bench Verified: 78.6%** – +4.6pp improvement over baseline (74.0%), 0.2pp behind official leaderboard leader (78.8%), 0.6pp behind Live-SWE-agent (79.2%). Ran SWE-bench baseline → automated root cause analysis → implemented targeted improvements → measured results
- **Agent006 x TAU Bench** – Using a vanilla Agent006 agent, some frontier models show improvements on Retail (+0.7pp to +3.7pp), mixed on Airline (Sonnet +9.5pp, Opus +1.0pp, Gemini -1.5pp). GPT-5 exhibits catastrophic failure on Retail (-29pp) from over-confidence on code execution. Smaller models also decline significantly in the codeact loop. We're updating our system prompts based on this.
- **Aligned with Nemo Evaluator team** – Working with Matt Staats and Michal Bien on [Harbor framework](https://harborframework.com/) integration to extend Nemo Evaluator to custom agents ([design doc](https://docs.google.com/document/d/1sdUDCsoYRNeToa4GHGZOo-PLqEKMotDeTjtmUER6g40/edit?tab=t.0#heading=h.ebwwwt269hcl)). Goal: common platform for apples-to-apples agentic evaluation at NVIDIA
- **Runtime available for experimentation** – Agent006 is available for hacking. Feedback welcome. Stable release planned in coming weeks.

**TAU Bench: Multi-Domain Agentic Evaluation**

*Led by Elisa Martinez Abad*

TAU Bench is a multi-domain benchmark evaluating agentic systems on real-world tasks across different customer service domains.

Top submissions report tuning prompts for model-specific failure cases without disclosing the tuned prompts, making direct comparison difficult. We've used the benchmark-provided prompts and agent (TAU ReAct) for an apples-to-apples comparison of a ReAct agent vs. a vanilla Agent006.

**Airline Domain Results (Pass@1)**

| Model | Agent006 Vanilla | TAU ReAct | Delta |
|-------|------------------|-----------|-------|
| Claude Sonnet 4.5 | 71.5% | 62.0% | +9.5pp |
| Claude Opus 4.5 | 68.0% | 67.0% | +1.0pp |
| Gemini 3 Pro | 66.5% | 68.0% | -1.5pp |
| GPT-5 | 60.5% | 59.5% | +1.0pp |
| Nemotron-3-Nano-30B | 39.5% | 49.0% | -9.5pp |
| Qwen3-Next-80B | 43.0% | 48.0% | -5.0pp |

**Retail Domain Results (Pass@1)**

| Model | Agent006 Vanilla | TAU ReAct | Delta |
|-------|------------------|-----------|-------|
| Claude Opus 4.5 | 84.6% | 80.9% | +3.7pp |
| Claude Sonnet 4.5 | 82.9% | 82.2% | +0.7pp |
| Gemini 3 Pro | 82.0% | 78.9% | +3.1pp |
| GPT-5 | 51.3% | 80.3% | -29.0pp |
| Nemotron-3-Nano-30B | 51.3% | 67.1% | -15.8pp |
| Qwen3-Next-80B | 25.9% | 60.3% | -34.4pp |

**Observations:**

- **Frontier models (Claude, Gemini)**: Some improvements on Retail (+0.7pp to +3.7pp). Mixed on Airline: Sonnet strong (+9.5pp), Opus marginal (+1.0pp), Gemini slight decline (-1.5pp)
- **GPT-5 over-confidence**: Catastrophic failure on Retail (-29.0pp). Model writes and submits code without checking execution results. Fine on Airline (+1.0pp)
- **Smaller model performance**: Significant declines across both domains. Smaller models find the Agent006 object interface confusing and start exploring the interface instead of solving the problem; we don't see this on simpler agents so we'll use this as a datapoint to revise our system prompts.

**Nemo Evaluator Integration via Harbor Framework**

We're working with the Nemo Evaluator / Eval Factory team to establish a common evaluation platform for agentic systems at NVIDIA. (Matt Staats, Michal Bien)

**The Problem:** Different teams evaluate agents differently, making it hard to compare results. Agent frameworks use different interfaces, making evaluation infrastructure hard to share.

**The Solution:** Use [Harbor framework](https://harborframework.com/) as a standard interface layer. Harbor provides a common API that:
- Wraps different agent frameworks (Agent006, LangGraph, Claude Code, OpenHands etc.) with a uniform interface
- Enables Nemo Evaluator to run benchmarks on any Harbor-compatible agent/benchmark
- Ensures apples-to-apples comparisons across teams at NVIDIA in the same way Eval Factory enables fair comparisons of model performance

**Status:** Proof-of-concept in progress. [Design doc](https://docs.google.com/document/d/1sdUDCsoYRNeToa4GHGZOo-PLqEKMotDeTjtmUER6g40/edit?tab=t.0#heading=h.ebwwwt269hcl).
