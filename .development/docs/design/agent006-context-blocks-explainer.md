# Agent006 & Context-Blocks: Agents as Objects

## The Core Idea

In Agent006, an **agent is just a Python object**. It lives in a Python runtime, has state, and calls methods—some implemented by you, some generated by an LLM. This stands in contrast to frameworks where agents are stateless functions orchestrated by external schedulers.

```python
class MyAgent(Agent, llm=my_llm):
    def __init__(self):
        super().__init__()
        self.memory = []       # Agent state - just Python
        self.knowledge = {}    # You control the data structures

    async def remember(self, fact: str):
        """Store a fact for later retrieval."""
        self.memory.append(fact)  # Normal Python code

    # LLM generates this implementation every call based on
    # the specific question, using a ReAct/REPL/CodeAct loop
    async def answer(self, question: str) -> str:
        """Answer the question using self.memory and self.knowledge."""
        ...
```

Because agents are objects, they can:

- Hold state across calls
- Be composed (agents containing agents)
- Be serialized and resumed
- Be tested like any Python class

## Context-Blocks: A Simple API for LLM Context

The **context-blocks** package provides a structured way to manage what the LLM sees. Instead of manually concatenating strings, you define **blocks**—small units of context with three controls:

| Expression | Purpose |
|------------|---------|
| `expr` | A python expression defining what to render (evaluates to content) |
| `update` | When to re-render (cache control) |
| `show` | When to show (visibility control) |

```python
# Blocks are Python expressions evaluated against agent state
Block(key="tools", expr="doc(self)", show="self.mode == 'explore'")
Block(key="recent", expr="self.memory[-10:]", update="True")
Block(key="persona", expr="self.persona", update="False")  # Cached
```

The **BlockManager** provides CRUD operations:

```python
agent.blocks.set("context", "focus", "self.current_goal")
agent.blocks.remove("context", "debug_info")
agent.blocks.list_keys("context")  # → ["tools", "focus", ...]
```

## History: Typed Conversation Events

History flows through the **HistoryManager**—a simple event bus:

```python
# Add events (UserEvent, AssistantEvent, ToolCallEvent, ToolResultEvent)
agent.history_manager.add(UserEvent(data=ContentData(content="Hello")))

# Query history
recent = agent.history_manager.recent(limit=20)
call_events = agent.history_manager.for_call(call_id)

# Subscribe to events in real-time
agent.history_manager.on("assistant", lambda e: print(e.data.content))
```

History is exposed to the LLM via an event block:

```python
Block(key="history", expr="self.history_manager.recent(limit=50)")
```

## The Goal: Agents Managing Their Own Memory

Because blocks are Python expressions evaluated at render time, and agents are objects with mutable state, **agents can programmatically control their own context**.

We imagine an agent that:

1. **Summarizes and compacts** old memories when context grows too large:

   ```python
   async def maybe_compact_memory(self):
       if len(self.memory) > 100:
           summary = await self.summarize(self.memory[:50])
           self.memory = [summary] + self.memory[50:]
   ```

2. **Promotes important facts** to a persistent knowledge base:

   ```python
   # Knowledge is always shown; raw memory only when exploring
   Block(key="knowledge", expr="self.knowledge", show="True")
   Block(key="memory", expr="self.memory", show="self.mode == 'recall'")
   ```

3. **Adapts context** based on the task:

   ```python
   # Before a math task, swap in the calculator docs
   with agent.blocks.scoped(context={"tools": "doc(self.calculator)"}):
       result = await agent.solve(problem)
   ```

4. **Learns retrieval strategies** by analyzing which memories led to success.

This is the key architectural bet: rather than building a fixed RAG pipeline or memory system, Agent006 provides primitives that let the agent (and the developer) experiment with memory strategies in code. The agent isn't a passive consumer of context—it's an active participant in constructing its own prompt.

## Summary

| Concept | What It Is |
|---------|-----------|
| **Agent** | A Python object with state, methods, and an LLM |
| **Block** | A unit of context with expr/update/show controls |
| **BlockManager** | CRUD API for managing blocks |
| **HistoryManager** | Event bus for conversation history |
| **The Promise** | Agents that programmatically manage their own memory |

The simplicity is intentional. Complex memory architectures can be built *on top* of these primitives, but the primitives themselves are just Python objects and expressions.
